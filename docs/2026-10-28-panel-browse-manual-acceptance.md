## 1. 家长可用性（3–5 位家长）

**数据：** 每位家长使用 5 份真实脱敏报告（至少含肝功 / 肾功 / 甲状腺 / 混合生化各一）。

**任务（主持人只读题，不提示路径；均从家庭首页开始）：**

1. 找到孩子的最近一次**肾功**结果。
2. 从家庭首页找到孩子的最近一次**肝功**结果。
3. 从家庭首页找到孩子的最近一次**甲状腺**结果。
4. 打开任一异常项目，说明该指标的异常 / 正常 / 未检测 / 待核对分别代表什么。
5. 说明「这份报告为什么同时出现在肝功和肾功」是否可理解。
6. 看家庭首页卡片，说出「现在谁需要处理、处理什么」。

**通过标准：** ≥4/5 家长无需帮助、每个任务 ≤4 次点按完成；能说出当前正在看哪位成员的档案；能看懂项目详情的异常 / 正常 / 未检测 / 待核对；能从家庭卡说出谁需要处理。

## 3. 部署 runbook（识别 → 迁移 → 回填 → App）

> 先 `snapshot` / `pg_dump` 备份；回填只写 `panel` 列，不改核对状态、修正对、值 / 单位 / 参考范围。

1. **备份**
   ```bash
   docker exec deploy-postgres-1 pg_dump -U healthyduoduo healthyduoduo > backup-before-panels.sql
   ```
2. **识别服务先行**：部署含 `panel` / `panels` / `POST /classify` 的 recognizer 镜像；`curl -fsS localhost:8000/healthz`。
3. **数据服务迁移**：部署新版 hdd 镜像；`hdd serve` 启动时执行内嵌迁移（含 `0011_report_panels`）。确认迁移成功后再进入下一步。
4. **存量回填**
   ```bash
   docker compose -p deploy -f deploy/docker-compose.yml exec hdd hdd backfill-panels --dry-run
   docker compose -p deploy -f deploy/docker-compose.yml exec hdd hdd backfill-panels
   ```
   完成标准：打印成功 / 跳过 / 失败计数；重复执行幂等；failed 报告保持 `panels=[]` 并跳过。识别服务不可用时命令失败并提示部署顺序。
5. **App 上线**：确认项目列表 / 项目详情 / 异常指标页可用；未回填存量按「其他」与 `report_type` 回退，不应出现空分类。
6. **回滚**：恢复步骤 1 的备份，回退 hdd / recognizer / App 镜像。App 端对 `panels=[]` 有 `report_type` 回退，回滚窗口内仍可浏览。

**验收勾选：**

- [ ] 备份文件可恢复（在临时库验证）
- [ ] 迁移成功且旧报告 `panels=[]` / `panel='other'` 初始状态符合预期
- [ ] `--dry-run` 与正式回填计数一致，重复执行幂等
- [ ] 回填后项目列表 / 详情逐项与报告详情一致
- [ ] failed 报告不进项目列表 / `?panel=`，按时间视图仍可见
