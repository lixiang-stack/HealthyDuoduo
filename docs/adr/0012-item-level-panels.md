# 0012 · 项目组按指标项分类，报告级只做聚合

**状态：** 采纳（2026-10-27，需求拷问与原型选型定稿）。

分类落到**指标项**：识别服务给每个指标项一个 `panel`，报告级 `panels` 是指标项面板按命中项数排序后的聚合，`panels[0]` 只用于卡片主标签。Go 数据服务只持久化 / 聚合 / 返回，不维护「指标名 → 项目组」映射；存量回填走识别服务 `POST /classify`，只更新 panel 列，不用 `/reparse` 重写指标项。

## 背景

- 产品要回答的是「孩子甲状腺最近怎么样、肝功有没有反复」，不是「这份报告属于哪个标签」。家长按肝功 / 肾功 / 甲状腺等体检项目找结果。
- 旧需求 v1 提出报告级多标签，v2.2 改为报告级单标签。两者都把分类停在报告级，无法回答项目内的跨报告趋势。
- 真实样本 49 份 golden 按「命中指标项数最多」模拟单标签：肾功 / 血脂 / 尿酸 / 电解质四个分类都是 **0 份**，但实际含这些指标的报告分别有 3 / 1 / 2 / 1 份；生化 15 份里 9 份归肝功。报告级单标签会让家长点「肾功」看不到任何报告。
- `GET /reports` 摘要不含指标名；客户端无法从摘要派生项目组。分类必须随识别输出，数据服务持久化 / 返回。
- 当前时间线按日期平铺；`report_type` 只用于 `/trends` 分组与首页「各类最近一次」。要修的是「缺少按项目浏览 / 跨报告聚合」，不是「替换时间线分类」。

## Considered Options

- **报告级单标签（v2.2）**：改动最小；但混合报告只进一个分类；样本里四个项目 0 份；项目详情只看最近一份报告，正常指标无历史。否。
- **报告级多标签（v1）**：混合报告进多个标签，解决「找不到」；但不解决「项目内指标趋势」；若按标签过滤指标，仍需指标级标签。否。
- **客户端派生 / Go 维护「指标名 → 项目组」映射**：摘要不含指标名，客户端要逐份拉详情；Go 维护映射会与识别端词典重复并漂移。否。
- **指标项级 `panel` + 报告级 `panels` 聚合**：识别服务在词典匹配时就知道每个指标属于哪个项目组；报告级只做计数排序；混合报告自然出现在多个项目下；项目详情直接按项目聚合指标与趋势。采纳。
- **回填用 `/reparse`**：reparse 会删除并重插 `report_items`，丢失核对状态与修正对。否。新增 `POST /classify`（report_type + 当前指标名 → panel）只更新 panel 列；与 postprocess 共用解析器。

## Consequences

- `recognizer/recognizer/contract.py` / `schemas/report.schema.json` 增加 `ReportItem.panel` 与 `Report.panels`；golden 全量更新。
- `report_items` 增加 `panel`，`reports` 增加有序 `panels text[]`；迁移 `0011`。不存 `primary_panel`，`panels[0]` 即主标签，避免两份真相。
- 报告摘要 / 详情暴露 `panels`；项目列表 / 详情新增两条成员维度端点；App 增加「按项目」视图。
- 识别服务新增内部 `POST /classify`；`hdd backfill-panels` 只更新 panel 列，保留 `review_status`、修正对与最终值。部署顺序：识别服务 → 迁移 → 回填 → App。
- `hdd backfill-panels` 跳过 failed 报告（无指标项、不进项目视图）：存量 `panels` 保持 `[]`，App 按 spec §7.3 回退 `report_type`；其余报告仅在项目组有差异时写库。
- 家长修正指标名后首版不自动重算 `panel`；`/classify` 已具备能力，但核对路径不调用。修正名不在词典时回填为 `other`。
- `other` 保留为唯一跨类别兜底；血型 / 肝纤维化 / 产前筛查 / 未归类进「其他」，UI 一行，行内显示来源报告类别。
- 混合报告在多个项目下出现；项目详情展示该项目全部指标，报告详情展示报告全部指标；不按项目过滤报告详情。
- 项目列表数据驱动，只显示当前成员实际出现过的项目；不产生空分类。
- 项目详情按 name+unit 分行，跨单位不合并、不换算；沿用既有趋势单位门控。
- 单标签的结构性缺陷被记录在案；未来若真实数据证明某些项目不应拆分，按 ADR 重新评审，而不是回到报告级单标签。
