# 0006 · 局域网先行，不做鉴权

**状态：** 采纳（2026-10-13，沿袭需求文档决策并经拷问确认）。

本期产品只部署在家庭局域网内（`hdd serve` + compose：postgres / seaweedfs / recognizer / hdd），HTTP API 与图像代理**均不做鉴权**，以家庭内网信任为安全边界，健康数据不出内网。配对二维码内容为**纯 URL 常量**（`http://<NAS 局域网 IP>:<端口>`，路由器 DHCP 保留保证 IP 稳定），手输兜底同串。

## 背景

家长侧 App 需要零配置连上家庭后端（扫码即用）。鉴权/账号体系对单家庭自用是纯摩擦，「30 秒一张检查单入档」的产品目标不允许注册登录拦路。部署双实例：Mac（arm64）= 开发与验证实例（M1 验收），NAS（amd64）= 家庭常驻实例（M2 验收），同一份 compose 两处复用、镜像双架构构建。

## Considered Options

- **引入鉴权（token/账号）**：对单设备单家庭是纯摩擦；公网化时另行立项评审——届时 API 已有 `/api/v1` 版本前缀与无状态请求形状，可插入鉴权中间件而不破坏契约形状。否（本期）。
- **mDNS 自动发现后端**：能免 DHCP 依赖，但复杂一个量级且各端实现不一。否——DHCP 保留 + 二维码常量 URL 已满足，且手输兜底同样拿到常量。

## Consequences

- 任何人处于同一局域网即可读写全部健康数据——这是**接受的边界**，不是疏忽。
- 公网暴露（端口映射/云部署）前必须重新评审（鉴权、TLS、审计）；本 ADR 是彼时评审的引用锚点。
- 局域网先行使「后端不可达」成为 App 的一等状态（离线队列），而非错误路径。
