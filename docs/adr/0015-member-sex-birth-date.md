# 0015 · 成员模型扩展：性别与出生日期

**状态：** 采纳（2026-11-02）。

## 背景

- 现有成员只有显示名与是否孩子两档，不足以选择年龄段参考区间、WHO 贫血切点与 BMI 百分位。
- 检验与判读依赖年龄和性别；静态年龄每年会过期，不能作为持久字段。
- 产品尚未上线，成员数据可以清空重建，不需要为存量数据设计兼容回填。

## 决策

1. `members` 新增 `sex`（`male` / `female` / `unspecified`）与 `birth_date`，两者 `NOT NULL`；新增 `birth_date_precision`（`day` / `year`，默认 `day`）。
2. 不存静态年龄；年龄由 `birth_date` 实时计算。
3. 只知出生年份时写当年 `01-01`，并标 `birth_date_precision = year`；避免 0–1 岁段按满岁计算。
4. `is_child` 保留，不删除、不按生日自动改写；既有 UI 与接口继续可用。
5. 建成员必须提供 `name` / `is_child` / `sex` / `birth_date`；`PATCH` 支持部分更新，必填字段显式 `null` 返回 400。
6. 迁移 0013 为破坏性操作，仅限未上线阶段：先把 `reports.member_id` 置空，再清空 `members`；报告、指标项与修正对保留，原图与 OCR 历史不动。不使用 `TRUNCATE members CASCADE`，因为它会连带清空 `reports`。
7. App 表单把性别做三选一，并提供出生日期精度切换；`year` 精度只收四位年份，提交时归一为 `YYYY-01-01`。

## Considered Options

- **保留年龄字段**：每年需要人工更新，跨年分析会悄悄用旧年龄。否。
- **性别只做男 / 女二选一**：家长在不确定时无法建档。否；增加 `unspecified`。
- **`TRUNCATE members CASCADE`**：SQL 最短，但会删除全部报告，与「报告保留、只解除归属」冲突。否。
- **为存量成员填默认性别 / 生日**：伪造数据会污染后续判读。否；未上线直接清空。
- **按生日自动改写 `is_child`**：改变既有语义且引入边界（18 岁整点）；本期不做。

## 后果

- 存量成员与报告归属被清空；报告、指标项与识别历史保留，`reports.member_id` 为 NULL。App 当前未选成员时不展示无主报告，需重新建成员后通过改归属接口/管理入口指派，才会回到时间线。
- 后续分析可直接按成员年龄与性别选择参考区间 / 切点，不再依赖静态年龄。
- `CONTEXT.md` 的成员定义、OpenAPI、App 表单与测试必须同步；`viz-and-client` 的成员最小模型假设自此失效。
- 迁移不可回滚数据；Down 只删除新增列，不恢复已清空的成员。
