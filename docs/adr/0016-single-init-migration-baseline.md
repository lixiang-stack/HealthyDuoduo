# 0016 · 未上线阶段收敛为单一 schema 基线（0019_init.sql）

**状态：** 采纳（2026-11-05）。

## 背景

- 产品未上线，数据库可以整体重建；迁移链（0001–0019）记录的是六周开发过程，不是当前 schema。
- 链里有空操作占位（0006）、一次性数据清理（0008）、破坏性成员重建（0013）和纯回填（0017–0019）。新库重放这些步骤没有意义。
- 开发库已停在 goose version 19；若把新基线命名为 0001，新库与旧库的 version 会分叉，后续迁移编号难以同时满足两边。

## 决策

- 用 **一个 `internal/storage/migrations/0019_init.sql`** 描述当前完整 schema（11 张表、9 个索引、11 个外键）。
- 保留 version **19**：已跑过旧 0018/0019 的库 goose 直接跳过；新库也落在 19。
- 后续迁移从 **0020** 开始编号，不再补 0001–0018。
- 迁移测试只验证当前 schema、约束与级联；不再保留逐版本 up/down 测试。

## Consequences

- 旧库无需 reset；处于中间版本（<19）的实验库必须重建，不提供跨版本升级路径。
- 上线后 schema 变更走正常的新迁移（0020+），不得再改写 0019。
- 迁移文件与 `docs/agents/contracts.md` 的镜像点同步维护。

## Considered Options

- **单文件命名为 0001**：新库 version 1、旧库 version 19，分叉难维护。否。
- **保留 0001–0019 全链**：对未上线产品是无收益的历史负担。否。
