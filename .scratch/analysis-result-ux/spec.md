# Spec：分析结果页 UX v2

Status: ready-for-human

**范围：** `apps/mobile` 分析结果页的信息架构、文案、来源/报告链接、状态与操作；不改变分析数据筛选、框架层规则或 LLM 输出契约。

**依据：** `.scratch/llm-analysis/spec.md`（分析引擎与契约）· `.scratch/analysis-result-ux/research.md`（六项验收发现、真机证据、外部 UX 依据）· `docs/adr/0012-item-level-panels.md` · `docs/adr/0013-native-only-acceptance.md`。

**研究结论：** 分析结果页目前是“证据优先、结论最后”，用户要先滚过报告清单、异常卡和历史趋势才能看到解读；`T-0` 等内部标记泄漏到界面；同一份报告可能同时出现在“本次范围”和“未纳入项”；来源链接不可操作；两个计数标题口径不同。详细证据见 `research.md`。

---

## 1. 为什么做

用户点「分析」想先得到“这意味着什么、下一步做什么”，而不是先看资料清单。当前页面把解释层放在最后，导致：

- 首屏没有结论，异常红色 flag 先于判读出现；
- 解读只覆盖部分异常时，用户会误以为全部异常都被解释；
- 时间窗口与项目范围混在一起，用户误以为“肝功不含胆红素”；
- 来源、报告、病历都不可追溯，削弱“可信、可核对”的产品边界；
- 正常值也会显示“升高/最高”，制造不必要焦虑。

## 2. 做什么

### 2.1 目标信息架构

把工程三层翻译成用户六层，按用户问题排序：

| 层级 | 回答的问题 | 内容 | 默认状态 |
| --- | --- | --- | --- |
| 0. 页头 | 这是谁、什么时候、看多长时间 | 成员、Panel、分析生成时间、6/12/24 个月窗口 | 一行 |
| 1. 结论 | 这意味着什么、严重吗、下一步 | 四段式解读 + 覆盖提示 + “不是诊断” + 依据 chip | 展开 |
| 2. 判读 | 规则怎么判 | 肝功判读；体格发育合并卡 | 肝功展开，体格折叠 |
| 3. 异常与变化 | 哪些数不对、在变好还是变差 | 偏离项（已解读/未覆盖）+ 历史趋势（有变化/单点） | 偏离展开，单点折叠 |
| 4. 医生记录 | 医生当时怎么说 | 诊断、处理原文；标注“当时/原文/不是建议” | 展开 |
| 5. 范围与局限 | 数据从哪来、没用什么 | 报告按窗口内/额外参考分组；未纳入项 + 无法比较 | 折叠 |
| 6. 操作 | 我能做什么 | 反馈、分享、重新分析、时间范围、查看原报告 | 底部 |

### 2.2 结论区

- 解读移到页头提示之后、其余事实块之前；解释不可用时在同一位置显示紧凑状态块。
- 解释卡内部顺序：可能原因（条目原文）→ 进一步检查 → 生活建议 → 长期跟踪 → 本次判据/查看依据。
- `bridge_text` 不再作为标题；默认收进「本次判据」或「查看依据」，用 12–13px muted 展示。
- 四段标题用 15px/600，正文 14px/21；组间距 ≥ 12px。
- 顶部显示“本次解读覆盖 N/M 项异常”；未覆盖项在偏离卡上标“未覆盖”，不生成未审核的医学解释。
- 病历卡使用“医生当时诊断/处理（原文，不是建议）”，并提示“请勿按旧处方自行用药”。

### 2.3 语言与计数

- `T-0` → 「最近一次」，`T-Nm` → 「约 N 个月前」；旧快照也要兼容。
- 偏离标题改为“各指标最近一次结果异常 N 项”，注明“按每项最近一次有效结果统计”。
- 历史标题改为“历史趋势 N 项”，注明“包含所有有有效数据的指标；其中 K 项只有 1 个点”，并说明其中多少项最近异常。
- 历史行点数改为中性色“共 N 个点”；正常值显示“本次在参考范围内”，不得只用“升高/最高”制造警示。
- `ULN` 首现写“正常上限”；同一指标全称/缩写一致；`unit=1` 不拼单位；统一 `unit_display`。

### 2.4 窗口与排除

- 顶部窗口行写明用户选择的 12 个月窗口；若 `sparse=true`，说明“部分指标历史数据较少，已按指标向前扩展参考，具体见各指标”。
- “本次范围”改为“本次使用的数据”，按报告日期分组：
  - 窗口内报告；
  - 因历史数据不足额外参考的报告（日期早于 `window.from`）。
- “未纳入项及原因”改为“未参与本次判断”，原因文案改为“超出该指标的时间窗口”，并显示来源报告日期。
- 明确说明：“项目范围决定看哪些指标，时间窗口决定看哪些日期；两者独立。”

### 2.5 来源、报告与操作

- 统一来源行：标准名 + 说明 + URL + 打开/复制；`accessibilityRole="link"`，触控区 ≥ 44×44。
- 优先使用已安装的 `expo-linking` 打开；复制方案待决策（`expo-clipboard` 或 `selectable` 兜底）。
- 报告日期、偏离卡日期、病历卡链接到 `/report/[report_id]`；返回后保留分析页。
- `stale` 提供“重新分析”，沿用原 panel/window，创建新快照；结果页可切换 6/12/24 个月。
- “这不对”改为明确范围（结果级 / 条目级），条目级反馈携带 `entry_id`。
- 显示分析生成时间；快照版本信息不展示给用户。

### 2.6 状态矩阵

| 状态 | 用户文案 | 下一步 |
| --- | --- | --- |
| 无条目 | 本次没有可引用的解读条目，可以带着上面的数值问医生 | 查看事实/框架层 |
| 额度用尽 | 今日额度已用完，事实与判读仍可用 | 明天再试；解释层不隐藏事实 |
| 云端失败 | 本次解释暂不可用 | 重试解读（不新建分析） |
| 部分拒绝 | 有 N 段解读未通过校验，已省略 | 反馈问题 |
| 截断 | 解释内容达到长度上限，已截断 | 查看事实层 |
| 旧分析 | 分析生成于 X；数据已更新/依据已更新 | 重新分析 |
| 证据不足 | 证据不足，请先核对 | 去核对 |
| 配额未知 | 额度状态暂不可用 | 稍后重试 |

“无条目”不显示空卡片，只显示固定引导；其余状态给原因、影响范围和动作。

## 3. 怎么实施

按 `issues/` 拆分，顺序：

1. `01-result-ia-v2.md`：结论优先、去重、折叠、六层分组（P0）。
2. `02-explanation-coverage.md`：解读覆盖提示、未覆盖异常、病历归因（P0）。
3. `03-traceable-links.md`：来源打开/复制、报告详情链接（P1）。
4. `04-window-exclusion.md`：窗口文案、报告分组、排除项日期（P1）。
5. `05-state-actions.md`：生成时间、部分拒绝、stale 重跑、范围切换（P1，部分需契约决策）。
6. `06-history-readability.md`：计数标题、正常状态、点数中性色、单点折叠（P1）。
7. `07-terminology-bmi.md`：术语、单位、BMI 合并（P1/P2）。
8. `08-feedback-observability.md`：条目级反馈、覆盖率/部分拒绝/trust gate 指标（P2）。

约束：

- 不改变事实层筛选、稀疏扩展、History 全量语义；只改展示口径。
- 不新增未审核的医学条目；未覆盖异常先明确标注，不等同于诊断。
- 旧分析快照必须兼容；不重跑历史分析。
- 契约变更（`created_at`、`entry_updated`、`partial_rejected` 等）先改 OpenAPI，再同步 Go/App/codegen/fixtures。

## 4. 怎么验收

- 393×873dp 首屏无需滚动即可看到“解读”标题和结论首句。
- 旧快照 `analysis 15` 上：解读覆盖 2/4 项；总蛋白/白蛋白标“暂无对应解读”。
- 2026-11-05 新增通用低蛋白/白蛋白条目后，新分析应覆盖 4/4；旧快照保持 2/4。
- 窗口显示 2025-11-04 至 2026-11-04，报告分为窗口内 3 份 / 额外参考 2 份；未纳入 7 项带 2025-09-28 日期，不再与“本次范围”矛盾。
- 页面不出现 `T-0` / `T-3m`；旧快照也能正确转换。
- 每个来源可打开或以可复制方式呈现；报告日期可进入报告详情。
- 正常值不再出现红色点数或单独的“升高/最高”警示。
- RNTL 覆盖：页序断言、4/14 计数、2/4 覆盖、8 个状态、链接打开/复制、旧快照兜底。
- 真机 smoke 按 `apps/mobile/ANDROID.md` 执行。

## 5. 非目标

- 不扩大 LLM 推理范围，不生成未审核的病因/治疗建议。
- 不改变 12/24 个月稀疏扩展算法。
- 不做全量异常分析入口。
- 不做病历与条目的自动冲突检测。

## 6. 待确认的产品决策

1. 无解读时是否显示紧凑状态块，而不是完全省略？
2. `bridge_text` 是否默认隐藏到“本次判据/查看依据”？
3. “可能原因”标题是否保留，还是改为“本次解读/这可能意味着”？
4. 稀疏扩展是否需要在每个指标上显示“该指标用了 24 个月”，还是只在顶部说明？
5. 历史趋势是否分组折叠，还是先只改标题/颜色？
6. 来源链接在 App 内打开（WebView）还是系统浏览器？
7. 是否新增 `expo-clipboard`（需要重建 dev build）？
8. 低蛋白/白蛋白是否新增审核条目，还是先只标“未覆盖”？
9. 病历药物/剂量是否默认折叠？
10. BMI 是否合并后从肝功页默认折叠，或移到成员首页？
11. 首批操作是否包含分享/导出，还是只做报告链接、重跑、条目反馈？
12. 是否为 `created_at` / `entry_updated` / `partial_rejected` 现在改契约？

## 7. 已确认决策（2026-11-04）

1. 无解读时显示紧凑状态块；`no_entries` 只给一行固定引导，不显示空卡片。
2. `bridge_text` 默认收进「查看本次判据」，12px muted 展示，不再作为标题。
3. 保留「可能原因」标题；四段式正文 14px/21、标题 15px/600。
4. 只修正 OpenAPI `window.from` 描述，不新增 `extended_from`；稀疏扩展按指标单独生效。
5. 历史采用方案 B：有变化项平铺，「仅 1 个点」默认折叠；不改变后端 History 全量语义。
6. 来源用系统浏览器打开（`expo-linking`），不新增 WebView。
7. 接受新增 `expo-clipboard`，用于一键复制与读屏播报；Expo Go 已内置。
8. 2026-11-05 更新：新增通用低蛋白/白蛋白条目（`liver-low-protein-albumin`，`any_flag_low` 触发），覆盖所有成员；旧快照仍显示「暂无对应解读」。独立医学复核待补。
9. 病历药物/剂量保留原文并展开，卡片内固定「请勿按旧处方自行用药」。
10. BMI 三标签合并为通用「体格发育」卡，所有项目结果页默认折叠。
11. 首批操作包含报告链接、stale 重跑、结果页范围切换、结果级/条目级反馈；分享/导出暂不做。
12. 2026-11-05 更新：`created_at` 已进 OpenAPI / Go / App / fixtures，结果页显示「生成于 YYYY-MM-DD HH:mm」。`entry_updated` / `partial_rejected` 仍不改契约；正向反馈、覆盖率指标、客户端事件与重试解读端点仍未做，记录在工单 05/08。

## 8. 2026-11-05 真机复核后的 IA 重审

真机验收后确认：当前问题不是单条文案，而是结果页同时承担了解释、数据浏览、趋势浏览和范围审计四个职责。详细分析、三个候选方案与推荐见：

- `.scratch/analysis-result-ux/prototype/README.md`
- `.scratch/analysis-result-ux/prototype/prototype.html`
- `.scratch/analysis-result-ux/prototype/shots/00-contact-sheet.png`

**已选方案 A（2026-11-05）。**

- 结果页只做「结论页」；历史趋势、窗口前参考、全部指标回已有肝功项目页；BMI 回成员页。
- 移除快照版本；「判据 / 依据」合并为一个来源入口；来源不展示原始 URL；反馈文案改为「反馈这段内容」。
- 「可能原因」的内容也使用圆点，与「下一步 / 长期跟踪」一致。
- 旧快照里总蛋白、白蛋白仍显示「暂无对应解读」；新条目上线后新分析覆盖 4/4。无论新旧，原因都不是数据过期或窗口外。
- 转氨酶与低蛋白/白蛋白的解读合并为一张汇总卡，按「可能原因 / 进一步检查 / 生活建议 / 长期跟踪」聚合，不再按指标分卡。
- 2026-11-05 补 `AnalysisResult.created_at`，结果页显示「生成于 YYYY-MM-DD HH:mm」；旧分析也显示原生成时间。

方案 B / C 保留在原型中作为对照，不进入本轮生产实现。实现清单见 `issues/09-result-conclusion-page.md`。
