# 护理记录产品重心 · 2026-11-23 原型

> 决策与实现边界见 `docs/adr/0019-care-log-navigation-child-context.md`；实现 spec 见 `.scratch/care-log/spec.md`；工单见 `.scratch/care-log/issues/`（01–08）。

## 这轮要选什么

护理记录放在哪里？四套可点击原型，同一套护理能力、同一组样例数据：

- **A · 档案优先**：家庭首页仍是报告档案；护理从成员卡的「今日护理」进入；统计 / 提醒是护理模块内的次级页面。
- **B1 · 日记优先（平铺）**：今天页成为首页；今天 / 统计 / 档案三个 tab 平铺。
- **B2 · 双域导航（域在底部）**：底部固定「日常 / 健康档案」，日常内部顶部再分「今天 / 统计」。
- **B3 · 双域导航（视图在底部）**：appbar 里切「日常 / 健康档案」，底部只显示当前域的视图；日常底部是「今天 / 统计」，健康档案底部是「报告 / 趋势」。**已确认（2026-11-23）。**

四套都包含喂养 / 尿布 / 睡眠 / 辅食记录、记录弹层、统计图表、提醒设置、报告档案与报告详情。差别只在**信息架构与首页重心**。

## 已确认的边界

- LAN-first / 无账号；不做家庭邀请、云同步、远程推送。
- 统计图表与提醒先做（品类标配）；就诊摘要后置。
- 护理事件标「家长记录」，不与检验值的信任标记混用。
- 提醒只在本机、用户设定、默认关闭，不承诺准时，不提供喂养建议。

## 怎么打开

直接用浏览器打开 `prototype.html`。顶部切换 A / B1 / B2 / B3；浮动条切换屏幕；关键路径可点击：

- A：家庭 → 「今日护理」→ 喂奶 → 保存 → 距上次喂养 / 今日时间线更新。
- 记录弹层：切换母乳 / 奶粉、改时间与数量、保存；点已有事件可修改或删除。
- A：统计 → 喂养 / 睡眠 / 尿布切换；提醒 → 开关 / 间隔。
- B1：今天 → 快捷记录 → 保存；统计 tab；档案 tab → 报告详情；提醒卡片 → 提醒设置。
- B2：底部日常 / 健康档案；日常内顶部今天 / 统计；健康档案底部 tab 有待核对小圆点。
- B3：appbar 里「日常 / 健康档案」；日常底部今天 / 统计；健康档案底部报告 / 趋势；默认日常 > 今天。B3 的统计页已接入 `charts.html` 的指标 × 图表类型切换（柱状 / 堆叠 / 折线），记录弹层显示「记录给 豆豆」。
- 顶部「空态」看第一次打开；「重置」恢复样例数据。

统计图表小原型：直接打开 `charts.html`，切换指标（喂养 / 奶量 / 睡眠 / 尿布）和图表类型（柱状 / 堆叠 / 折线），看每种图回答什么问题。截图参数 `?metric=amount&chart=bar&clean=1`。

一级导航呈现小原型：直接打开 `nav.html`，切换四种放法——顶部独立 segmented / 嵌进 appbar 的域 tab / 标题下拉 / 首页双卡。截图参数 `?variant=top|appbar|dropdown|hub&clean=1`。

截图参数：

```text
?scenario=A|B|C|D&screen=<screen>&clean=1&sheet=feed&reminder=on&empty=1
```

`clean=1` 只渲染 390×844 手机屏，用于截图。`sheet=feed|diaper|sleep|solid` 打开记录弹层；`reminder=on` 预置提醒开启；`empty=1` 清空今日记录。

## 统计图表小原型

- **柱状**：每天多少；适合 7 天总量对比，不适合构成 / 趋势 / 分布。
- **堆叠**：每天由什么组成；睡眠夜间/白天、尿布尿/便/混合、母乳/奶粉。
- **折线**：往哪走；适合 30 天趋势，7 天窗口下和柱状差别不大。
- **直方图**：分布；只用于喂养间隔 / 单次奶量，不用于每日总量（本原型未做）。
- **建议顺序**：先保留柱状；需要构成时加堆叠；30 天趋势再用折线；不要为了「统计看起来丰富」而给每个指标配三种图。

## 多照护者与孩子上下文

- 爸爸 / 妈妈各自设备共用同一 LAN 后端；成员列表共享，但「当前孩子」是每台设备的本地状态。
- 单孩子：自动选中；多孩子：每台设备选一次并记住。appbar、今天页 hero、记录弹层都显示孩子名。
- 记录弹层标题写「记录给 豆豆」；多孩子时必须先选孩子才能保存。
- 不做全局 active child（两台设备可能同时记录不同孩子）；不做账号 / 记录人归属，记录仍标「家长记录」。
- 同一孩子短时间内重复记录：保存前提示「刚刚已有一条喂养记录」，由家长决定是否继续。

## 一级导航呈现

- **A 顶部独立 segmented**（fallback）：多占 46px，两个域一眼可见；最稳。
- **B appbar tabs**（已确认，2026-11-23）：把「日常 / 健康档案」放进 appbar，省 46px，两个域仍一眼可见。
- **C 标题下拉**：标题「日常 ▾」点开切换；省 46px，但另个域藏在点击后，适合低频切换。
- **D 首页双卡**：打开先选域；并列最清楚，但每天多一次点击，适合把两个域当两种模式。
- **结论**：已确认 B；A 作为保守 fallback；C / D 不采用。

## 今日时间线呈现（2026-11-24）

目标：在展示和交互上突出时间线。已确认「最新在上」与四类轻量色（喂养蓝 / 尿布琥珀 / 睡眠靛 / 辅食橙）；密度、上方内容待选。

- **A · 时间轨 + 事件节点**（推荐）：左侧时间栏 + 贯穿竖轨 + 类型节点；行高最高，扫读最快，最像时间线。
- **B · 间隔线**（低风险）：保留紧凑行，只在事件间显示「间隔 2 小时 10 分」；视觉最轻。
- **C · 24 小时概览 + 明细**：顶部 24h 比例轴 + 最新在上明细。纯纵向 24h 轴需要按时间正序，与「最新在上」冲突，因此本原型采用「概览轴 + 最新在上列表」。

打开 `timeline.html`，底部浮动条切换 A/B/C、密度、上方内容、空态与时间线特写；也支持 URL 参数：

```text
?variant=A|B|C&density=comfortable|compact&top=current|compressed&state=events|empty&view=phone|timeline&clean=1
?contact=1
```

## 需要你判断

1. 第一屏是谁：A 的家庭 / 报告，还是 B 的今天 / 护理？
2. 一级导航：已确认 appbar tabs；B2 的底部全局 tab 不采用。
3. 进入日常后，底部只留今天 / 统计是否更顺？健康档案只在顶部保留入口是否够？
4. 首次启动默认进日常 > 今天，还是让家长选一次 / 记住上次所在的域？
5. 一级域叫「日常」还是「喂养」？如果以后加尿布 / 睡眠 / 辅食，哪个名字还成立？
6. 你的家庭真实使用时，会每天打开 A 还是 B？会频繁切到健康档案吗？
7. 提醒要不要独立成 tab？原型目前放在今天页卡片 + 提醒设置；如果只是开关 + 间隔，不建议占一个 tab。
8. 统计图表是否只保留柱状？建议先保留；下一步优先堆叠柱状图表达构成，30 天趋势再加折线；直方图只用于间隔 / 单次奶量分布。
9. 一级导航放哪里：已确认 appbar tabs（B）；C / D 不采用。

## 边界

- 这是丢弃式原型，不是生产实现；数据为合成样例。
- 统计 / 提醒是品类标配，不是本产品的护城河；它们的作用是让护理记录可用，不替代报告、核对与解读。
- 不包含账号、云同步、家庭邀请、远程推送、医疗建议。
- B3 的「健康档案不在底部」只表示**不在日常的底部导航里**，不是把健康档案从产品中删除；它仍在 appbar 一级域入口，并保留待核对小圆点。
