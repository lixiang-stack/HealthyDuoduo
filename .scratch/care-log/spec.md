# Spec：B3 护理记录导航与孩子上下文

Status: **implemented / accepted with known gaps**（2026-11-23 用户确认 B3 + appbar tabs；2026-11-24 票 01–08 跨票验收通过；差异见 §15）

范围：App 一级 / 二级导航、当前孩子、记录弹层目标、重复喂养提示、提醒入口、统计页入口与空态。不含护理事件表 / API / OCR / 报告分析实现；护理事件数据模型按 `docs/reference/wechat-feeding-tracker.md` §7 另立实现 spec。

依据：`docs/adr/0019-care-log-navigation-child-context.md` · `../../docs/adr/0006-lan-first-no-auth.md` · `../../docs/adr/0013-native-only-acceptance.md` · `../../CONTEXT.md` · 原型 `prototype/prototype.html`、`prototype/nav.html`、`prototype/charts.html`。

## 1. 为什么做

产品长期要从「检查报告档案」扩展到「健康育儿」。日常护理记录是高频入口，但爸爸、妈妈可能各自用自己的设备记录同一个孩子；在 LAN-first、无账号的前提下，不能靠登录身份判断「谁在记」，也不能让两台设备共享一个全局「当前孩子」——两边可能同时记录不同孩子。

因此需要同时解决两件事：

1. **导航层级**：育儿与健康档案是并列的两个域；高频的「今天 / 统计」放底部，低频的域切换放 appbar。避免 B1 把「档案」和「今天 / 统计」放在同一层。
2. **孩子上下文**：每台设备明确「当前记录给哪个孩子」，并在育儿页左上角、hero、记录弹层三处可见；事件以 `member_id` 落库，不以设备状态为准。

## 2. 目标与非目标

### 2.1 目标

1. 爸爸、妈妈各自设备都能在 1 次点击内进入「育儿 > 今天」并开始记录。
2. 两台设备都能明确看到当前孩子；多孩子家庭不会把事件静默记到错误孩子名下。
3. 单孩子家庭没有额外选择成本；多孩子家庭每台设备只选一次并记住。
4. 同一孩子短时间内的重复喂养会被提示，但不自动合并、不阻塞。
5. 不引入账号、邀请、云同步、记录人归属；保持 ADR-0006 的边界。

### 2.2 非目标

- 账号、家庭邀请、绑定 / 解绑、角色 / 权限、跨家庭隔离。
- 云同步、远程推送、跨公网访问。
- 记录人归属（爸爸 / 妈妈）或任何 `recorded_by` 字段。
- 服务端全局 active child。
- 提醒独立 tab、提醒计划 / 历史、系统级准时推送。
- 护理事件写入报告、项目组、趋势或分析快照。
- 直方图、PDF 导出、就诊摘要。
- 成人成员的护理记录。

## 3. 术语

- **育儿**：护理记录的产品域，含今天 / 统计；与健康档案并列。定义仍是护理记录（喂养 / 尿布 / 睡眠 / 辅食），不扩展为育儿建议、内容或社区。
- **健康档案**：报告、核对、趋势的产品域。
- **当前孩子**：某台设备上当前选中的护理对象；单孩子自动选中并锁定，多孩子本地选择并记住。不是全局状态。
- **记录目标**：记录弹层打开时冻结的孩子；保存时写入该孩子的 `member_id`，不随育儿页后续切换而改变。
- **护理事件**：喂养、尿布、睡眠、辅食等日常记录；与检查报告是不同领域，不混表。
- **家长记录**：护理事件的来源标签；不代表已验证的测量值，也不标识具体记录人。

> 实现时把「育儿 / 健康档案 / 当前孩子」补进 `CONTEXT.md`；本 spec 先锁定行为。

## 4. 信息架构

### 4.1 Appbar（一级域）

```text
育儿   健康档案 •
────────────────────────────────────
```

- 左侧两个文本 tab：育儿 / 健康档案；当前域加粗 + 底部 2px 蓝色下划线。
- 健康档案 tab 带待核对小圆点（有可操作待核对项时显示）。
- appbar 不承载当前孩子；当前孩子入口在育儿页内容区左上角（见 §5.2），避免与域 tab 争位置。
- appbar 不显示页面标题；二级视图名由底部 tab 承担（今天 / 统计 / 报告 / 趋势）。
- 域切换保持各自域上次的二级 tab；点当前域回到该域根视图（育儿 → 今天；健康档案 → 报告）。

### 4.2 底部 contextual tabs（二级视图）

| 当前域 | 底部 tab | 默认 |
| --- | --- | --- |
| 育儿 | 今天 / 统计 | 今天 |
| 健康档案 | 报告 / 趋势 | 报告 |

- 进入育儿后底部不出现健康档案；进入健康档案后底部不出现育儿。
- 最多两个底部 tab；不新增「记录」「提醒」「设置」tab。
- 「记录」是今天页上的快捷动作 + 记录弹层。

### 4.3 默认入口

1. 首次启动且无本地偏好：
   - 有孩子成员 → 育儿 > 今天。
   - 无孩子成员 → 健康档案 > 报告；育儿入口显示空态。
2. 首次启动可显示一次「记录今天 / 查看健康档案」选择（原型 welcome 屏）；选择后记住。
3. 之后记住上次所在的域与二级 tab；冷启动回到上次位置。
4. 当前成员是成人时不影响育儿页：育儿只消费当前孩子，不把成人作为护理事件目标；健康档案仍可切换成人看报告。

> 默认入口是产品建议；首个真实使用周期验证「是否每次都落到育儿」后再调整。

### 4.4 页面

- **育儿 > 今天**：hero「豆豆 · 距上次喂养」、四个快捷动作、今日摘要、提醒卡片、今日时间线（独立「全部记录」入口未接线，见 §15.8）。
- **育儿 > 统计**：指标 tab（喂养 / 奶量 / 睡眠 / 尿布）、图表类型（柱状 / 堆叠 / 折线）、3 个 KPI、图表、图注与建议；不重复放提醒卡片。
- **健康档案 > 报告**：成员 chips、按时间 / 按项目、报告卡、识别失败重试。
- **健康档案 > 趋势**：指标趋势列表；后续可扩展。
- **报告详情 / 今日记录 / 提醒**：栈页面，带返回；不显示底部 tab。
- **记录弹层**：从今天页打开；标题下固定显示「记录给 豆豆 · 当前孩子」。

## 5. 当前孩子

### 5.1 数据与存储

- 成员列表来自现有 `GET /members`；`is_child` 由出生日期实时计算，不新增字段。
- 每台设备本地保存 `currentMemberId`（健康档案查看对象）与 `currentChildId`（育儿记录对象），均为 AsyncStorage；不写服务端。
- 单孩子：自动选中并锁定；只显示名字，不显示选择箭头，不需要选择器。
- 多孩子：首次进入育儿页时要求选择；之后记住。清除 App 数据 / 换设备后重新选择。
- 当前孩子被删除：清空本地选择；仍有多个孩子则打开选择器；只剩一个则自动选中并锁定；没有孩子则育儿页显示空态；首次启动 / 无本地偏好时默认入口落到健康档案。
- 成人成员不作为护理目标；健康档案仍可切换成人查看报告。

### 5.2 展示

- 育儿页内容区左上角：`豆豆 ▾`（单孩子只显示名字）。
- 今天 hero：`豆豆 · 距上次喂养`。
- 记录弹层：`记录给 豆豆` + `当前孩子` 标签。
- 三处必须使用同一个 `member_id`；不能只显示昵称而不绑定 id。

### 5.3 切换孩子

- 点击育儿页左上角 `豆豆 ▾` 打开选择器；只列孩子；选择器含「管理成员」入口；健康档案在页内成员 chips 中列全部成员。
- 切换后：今天 / 统计 / 时间线立即刷新到新孩子；各孩子的二级 tab 状态可保留。
- 记录弹层打开后切换育儿页孩子：弹层目标不跟着变；弹层里的「记录给」是最终保存目标。
- 不做全局 active child；两台设备独立选择。

## 6. 记录弹层与重复提示

### 6.1 记录弹层

- 入口：今天页四个快捷动作；时间线点击已有事件进入修改。
- 标题：记录喂奶 / 尿布 / 睡觉 / 辅食；修改时为「修改记录」。
- 标题下固定一行：`记录给 豆豆` + `当前孩子` 标签。
- 多孩子时，弹层顶部增加孩子 chips；未选孩子不能保存；单孩子也显示目标但不需要 chips。
- 保存时使用弹层冻结的 `member_id`，不读取保存瞬间的育儿页选择。
- 空值规则沿用原型：喂奶类型必选、时间默认现在、数量 / 备注可选；辅食食物必填。

### 6.2 重复喂养提示

- 触发：保存「喂养」事件前，查询同一 `member_id` 最近一条喂养事件；若距当前时间 ≤ 5 分钟，且不是正在修改的同一条事件。
- 文案：`刚刚已有一条喂养记录（14:05 · 奶粉 120 ml），仍然添加？`
- 动作：`仍然添加` / `返回修改`；不自动合并、不服务端去重。
- 常量：`DUPLICATE_FEED_WINDOW_MINUTES = 5`（建议值，真实使用后调整）。
- 跨设备并发：两台设备可能在窗口内各保存一次；提示是 best-effort，不能保证拦截。

### 6.3 记录人

- 不存 `recorded_by`、不显示爸爸 / 妈妈头像或名字。
- 事件来源统一显示「家长记录」；与检验值的信任标记区分。
- 如未来需要真实记录人，另开 ADR 评审账号 / 设备身份 / 审计。

---

## 7. 提醒

- 不是 tab，不在统计页重复放卡片。
- 唯一入口：今天页提醒卡片 → 提醒设置栈页。
- 本机通知、默认关闭、用户设定间隔（2 / 3 / 4 小时）、不承诺准时、不提供喂养建议。
- 没有账号 / 云同步 / 远程推送；记录仍可在同一 LAN 的其他设备查看。

---

## 8. 统计

- 育儿 > 统计；指标：喂养 / 奶量 / 睡眠 / 尿布；图表：柱状 / 堆叠 / 折线。
- 柱状回答「每天多少」；堆叠回答「由什么组成」；折线回答「往哪走」；直方图不在本期。
- 3 个 KPI + 图表 + 一句图注 + 选图建议；不重复放提醒。
- 无数据：显示「还没有记录」+ 去今天页；只有一个数据点时图表照常渲染，不伪造趋势。
- 统计不新增一级 / 二级导航层级；图表类型只在统计页内部切换。

## 9. 怎么实施

1. **路由**：用两个域分组承载 B3：`/care`（今天 / 统计）与 `/health`（报告 / 趋势）；appbar 域 tab 在两组之间切换，底部 tab 由各组自己的 tab layout 渲染。报告详情 / 今日记录 / 提醒为栈页面。
2. **Appbar**：新增共享 `DomainTabs` 组件；接收 active domain、健康档案待核对计数；域切换用 `router.replace` 保留各域上次二级 tab。当前孩子不放 appbar，改在育儿页内容区左上角。
3. **孩子上下文**：扩展现有 `CurrentMemberContext`，增加 `currentChildId` / `setCurrentChild`；AsyncStorage 持久化；单孩子自动选中并锁定；多孩子选择器；成员删除时清理。
4. **记录弹层**：打开时冻结 `targetMemberId`；多孩子 chips；保存禁用条件；保存后刷新当前孩子今天数据。
5. **重复提示**：保存前用最近喂养事件做客户端判断；常量集中定义；不新增服务端接口。
6. **统计**：复用 `charts.html` 的 4 指标 × 3 图表数据形状与渲染；接入现有护理事件读模型；无数据空态。
7. **提醒**：保留今天卡片与设置页；移除统计页的提醒卡片（若现有实现有）。
8. **文档**：实现时把「育儿 / 健康档案 / 当前孩子」补进 `CONTEXT.md`；护理事件表 / API 按调研文档 §7 另立实现 spec。

## 10. 怎么验收

### 10.1 RNTL 屏幕测试

1. appbar 两个域 tab；育儿底部今天 / 统计，健康档案底部报告 / 趋势；切换域保留各自二级 tab。
2. 单孩子：自动选中并锁定；育儿页左上角、hero、记录弹层三处显示同一孩子；单孩子不显示选择箭头。
3. 多孩子：首次进入要求选择；选择持久化；选择器含「管理成员」；切换孩子后今天 / 统计刷新；两台设备状态互不影响（用两个 context 实例模拟）。
4. 记录弹层：显示「记录给 X」；多孩子未选不能保存；保存事件的 `member_id` 等于弹层目标，不等于保存瞬间的育儿页选择。
5. 重复提示：同孩子 5 分钟内已有喂养 → 弹确认；选「仍然添加」落两条；选「返回修改」不落库；修改同一条不触发。
6. 提醒：不在底部 tab；今天卡片可进设置；统计页无提醒卡片。
7. 统计：4 指标 × 3 图表切换；空态不显示假数据；无提醒卡片。
8. 无账号 / 记录人 UI：不出现爸爸 / 妈妈归属；事件统一「家长记录」。

### 10.2 Android 真机 smoke

- appbar 域 tab 点击、下划线、健康档案圆点。
- 孩子选择器：单孩子 / 多孩子 / 删除孩子后的回落。
- 记录弹层：目标孩子、切换孩子、保存、重复提示。
- 底部 tab 随域变化、二级 tab 状态保留、返回键行为。
- 统计图表在窄屏、长标签、无数据下的布局。
- 提醒设置与今天卡片跳转。

### 10.3 数据 / 契约

- 护理事件必须有 `member_id`；不新增 `recorded_by`、`device_id`、全局 active child 字段。
- 不新增鉴权 / 账号表；沿用 ADR-0006。
- 护理事件不写入 `reports` / `report_items` / 趋势 / 分析快照。
- 护理事件 API / 表按调研文档 §7 另立实现 spec 后再动契约。

## 11. 风险与假设

- **appbar 拥挤**：当前只有两个域 + 待核对圆点；加入通知 / 搜索后仍可能放不下；fallback 是顶部独立 segmented，需重新截图与测试。
- **多孩子误选**：三处显示 + 弹层确认只能降低，不能消除；真实使用后看是否需要在保存前二次确认。
- **重复提示误报 / 漏报**：5 分钟窗口是建议值；跨设备并发可能漏报；不做自动去重是明确取舍。
- **无真实用户验证**：爸爸 / 妈妈同时使用、切换孩子频率、重复记录窗口都还是假设；上线前按 §10 和调研文档 §7.5 验证。
- **护理事件数据模型未实现**：本 spec 只锁导航与孩子上下文；`feeding_events` / 尿布 / 睡眠等表与 API 尚未落地。

## 12. 开放问题

1. 默认入口是否长期保持「育儿 > 今天」，还是按孩子年龄 / 使用频率动态？本 spec 先固定，真实使用后再评估。
2. 多孩子选择器用底部弹层还是全屏页？本 spec 不锁定，按现有 App 组件选型；票 03 采用底部弹层。
3. 重复窗口 5 分钟是否合适？需要真实家庭数据校准。
4. 成人成员是否显示育儿入口？已定（2026-11-23）：育儿页只消费当前孩子，成人当前成员不影响；健康档案仍可切成人看报告。
