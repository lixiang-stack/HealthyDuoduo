# 04: 记录弹层与目标孩子

**What to build:** 从今天页打开记录弹层，标题下固定显示「记录给 豆豆 · 当前孩子」；多孩子时先选目标孩子才能保存；弹层打开时冻结目标，保存事件的 `member_id` 等于弹层目标，而不是保存瞬间的 appbar 选择。覆盖喂奶 / 尿布 / 睡觉 / 辅食的创建、修改、删除。

**Blocked by:** 01（护理事件契约）、03（当前孩子上下文）。

**Status:** resolved

## 验收清单

- [x] 今天页四个快捷动作打开对应记录弹层；标题为记录喂奶 / 尿布 / 睡觉 / 辅食，修改时为「修改记录」。
- [x] 标题下固定一行：`记录给 豆豆` + `当前孩子` 标签；多孩子时弹层顶部有孩子 chips。
- [x] 多孩子未选目标时保存按钮禁用；单孩子显示目标但不需要 chips；成人不能成为目标。
- [x] 弹层打开时冻结 `targetMemberId`；打开后切换 appbar 孩子不改变保存目标；保存后事件 `member_id` 等于弹层目标。
- [x] 保存后今天时间线 / 距上次喂养 / 今日摘要刷新；修改、删除已有事件后同步刷新。
- [x] 字段规则：喂奶类型必选、时间默认现在、数量 / 备注可选；辅食食物必填；时间 / 数量非法值有校验。
- [x] 所有事件标「家长记录」；不出现 `recorded_by`、爸爸 / 妈妈头像或名字。
- [x] 记录弹层不写入报告 / 趋势 / 分析表；跨孩子事件不混入当前时间线。
- [x] RNTL：目标显示、多孩子保存禁用、目标冻结、保存 `member_id`、编辑 / 删除、字段校验、无记录人 UI。

## 实现提示

- 用 01 的 `CareEvent` 契约与 adapter；没有正式 API 时用 fixture + 本地状态，接口形状保持一致。
- 弹层打开时把当前孩子复制到 `targetMemberId`；保存只读这个值。
- 多孩子 chips 只列 `is_child` 成员；单孩子不显示 chips，但保留目标行。
- 编辑已有事件时沿用事件原 `member_id`，不要因为 appbar 当前孩子变化而改归属。
- 空值 / 非法值沿用现有表单口径；不要新增全局表单库。

## Comments

**实现（2026-11-23）：**
- 今天页接入护理事件读模型：`CareEventProvider` 默认 `InMemoryCareEventRepository` + `CARE_EVENT_FIXTURES`（HTTP adapter 后续替换）；`useTodayCareEvents` 读取「昨天 + 今天」两天，时间线 / 摘要只取本机今天，hero 的「距上次喂养」可用昨天的最后一条，跨午夜不归零。
- `TodayCareLog` 显示 hero、四个快捷动作、今日摘要、今日时间线；`RecordSheet` 在挂载时冻结当前孩子为目标，多孩子 chips 只列 `is_child`，成人过滤；单孩子不显示 chips；未选目标禁用保存；编辑沿用事件原 `member_id` 且不显示 chips。
- 字段：喂奶方式显式必选（不默认奶粉，避免静默记错）；时间默认现在并校验 `HH:MM`；奶量 / 时长 / 克数必须为正数；辅食食物必填；备注 trim 为空存 `null`；sleep 有 duration 时派生 `ended_at`。
- 保存 / 修改 / 删除后刷新时间线、hero 与摘要；跨孩子事件按 `member_id` 隔离；事件行、hero 与弹层标「家长记录」，不引入 `recorded_by` / 设备 / 记录人字段。
- 修复 01 契约的范围语义：`ended_at = null` 对 sleep 表示进行中，对 feed / diaper / solid 表示瞬时事件，避免前一天的喂养 / 尿布 / 辅食永久出现在之后的「今天」；同步契约文档与测试。
- 代码评审后修正：编辑喂养也进入重复检查；今天页读取昨天 + 今天以保证 hero 跨午夜不归零；加载失败不再显示空态或 0 摘要；把字段表单拆到 `RecordFields`。
- 取舍：删除沿用原型立即删除，不额外确认；喂奶方式不预选；多孩子编辑时不显示 chips（update 不改 `member_id`）；提醒卡（06）和统计（07）不在本票。
- 已知限制：护理事件仍是内存 adapter，重启 App 后回到 fixture；正式 API 落地后按同一接口替换。
