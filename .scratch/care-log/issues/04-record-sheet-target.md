# 04: 记录弹层与目标孩子

**What to build:** 从今天页打开记录弹层，标题下固定显示「记录给 豆豆 · 当前孩子」；多孩子时先选目标孩子才能保存；弹层打开时冻结目标，保存事件的 `member_id` 等于弹层目标，而不是保存瞬间的 appbar 选择。覆盖喂奶 / 尿布 / 睡觉 / 辅食的创建、修改、删除。

**Blocked by:** 01（护理事件契约）、03（当前孩子上下文）。

**Status:** ready-for-agent

## 验收清单

- [ ] 今天页四个快捷动作打开对应记录弹层；标题为记录喂奶 / 尿布 / 睡觉 / 辅食，修改时为「修改记录」。
- [ ] 标题下固定一行：`记录给 豆豆` + `当前孩子` 标签；多孩子时弹层顶部有孩子 chips。
- [ ] 多孩子未选目标时保存按钮禁用；单孩子显示目标但不需要 chips；成人不能成为目标。
- [ ] 弹层打开时冻结 `targetMemberId`；打开后切换 appbar 孩子不改变保存目标；保存后事件 `member_id` 等于弹层目标。
- [ ] 保存后今天时间线 / 距上次喂养 / 今日摘要刷新；修改、删除已有事件后同步刷新。
- [ ] 字段规则：喂奶类型必选、时间默认现在、数量 / 备注可选；辅食食物必填；时间 / 数量非法值有校验。
- [ ] 所有事件标「家长记录」；不出现 `recorded_by`、爸爸 / 妈妈头像或名字。
- [ ] 记录弹层不写入报告 / 趋势 / 分析表；跨孩子事件不混入当前时间线。
- [ ] RNTL：目标显示、多孩子保存禁用、目标冻结、保存 `member_id`、编辑 / 删除、字段校验、无记录人 UI。

## 实现提示

- 用 01 的 `CareEvent` 契约与 adapter；没有正式 API 时用 fixture + 本地状态，接口形状保持一致。
- 弹层打开时把当前孩子复制到 `targetMemberId`；保存只读这个值。
- 多孩子 chips 只列 `is_child` 成员；单孩子不显示 chips，但保留目标行。
- 编辑已有事件时沿用事件原 `member_id`，不要因为 appbar 当前孩子变化而改归属。
- 空值 / 非法值沿用现有表单口径；不要新增全局表单库。
