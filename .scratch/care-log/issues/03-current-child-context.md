# 03: 当前孩子上下文（设备本地）

**What to build:** 每台设备明确「当前记录给哪个孩子」：单孩子自动选中；多孩子选择并记住；成人成员不作为护理目标；当前孩子被删除 / 清空后正确回落。当前孩子只存本地，不写服务端全局状态。

**Blocked by:** 02（导航壳 / appbar 孩子槽位）。

**Status:** ready-for-agent

## 验收清单

- [ ] 扩展当前成员上下文，增加 `currentChildId` / `setCurrentChild`；用 AsyncStorage 持久化，不新增服务端字段。
- [ ] 单孩子：自动选中该孩子；appbar、今天 hero、记录弹层三处显示同一孩子。
- [ ] 多孩子：首次进入日常要求选择；选择后记住；换设备 / 清除数据后重新选择。
- [ ] 成人成员：不作为护理目标；当前成员是成人时日常入口引导选择孩子；健康档案仍可切换成人看报告。
- [ ] 无孩子成员：日常显示空态并引导建孩子；默认落到健康档案。
- [ ] 当前孩子被删除：清空本地选择；仍有其他孩子则打开选择器；没有孩子则切到健康档案。
- [ ] 两台设备独立：用两个 context 实例模拟，设备 A 选豆豆、设备 B 选老二，互不覆盖；事件仍以 `member_id` 归属。
- [ ] appbar 右侧 `豆豆 ▾` 可打开选择器；日常只列孩子，健康档案列全部成员。
- [ ] 不新增账号 / 邀请 / 云同步；不写全局 active child。
- [ ] RNTL：单孩子自动、多孩子选择持久化、成人引导、无孩子回落、删除孩子回落、双设备独立。

## 实现提示

- 现有 `CurrentMemberContext` 已管理成员选择；本票只补「当前孩子」派生与持久化，不重写成员加载。
- 单孩子判定用 `is_child`（由出生日期实时计算），不新增字段。
- 选择器可复用现有成员 chips 的样式；日常场景过滤 `is_child`。
- 测试用 mock 成员列表覆盖 0 / 1 / 多孩子、成人、删除；不要依赖真实后端。
