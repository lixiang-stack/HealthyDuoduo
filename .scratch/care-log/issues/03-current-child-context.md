# 03: 当前孩子上下文（设备本地）

**What to build:** 每台设备明确「当前记录给哪个孩子」：单孩子自动选中并锁定；多孩子选择并记住；成人成员不作为护理目标；当前孩子被删除 / 清空后正确回落。当前孩子只存本地，不写服务端全局状态。育儿页左上角承载当前孩子上下文；票 02 的 appbar 右侧 `孩子 ▾` 占位在本票替换。

**Blocked by:** 02（导航壳）。

**Status:** ready-for-agent

## 验收清单

- [x] 域 tab 文案改为「育儿 / 健康档案」；路由可暂保留 `/daily`，用户可见文案与 `CONTEXT.md` 使用「育儿」。
- [x] 扩展当前成员上下文，增加 `currentChildId` / `setCurrentChild`；用 AsyncStorage 持久化，不新增服务端字段。
- [x] 单孩子：自动选中并锁定；育儿页左上角显示当前孩子；单孩子不显示选择箭头（今天 hero / 记录弹层在票 04 消费同一 `currentChildId`）。
- [x] 多孩子：首次进入育儿页要求选择；选择后记住；换设备 / 清除数据后重新选择。
- [x] 成人成员：不作为护理目标；育儿页只消费 `currentChildId`，不受当前成员身份影响；健康档案仍可切换成人看报告。
- [x] 无孩子成员：育儿页显示空态并引导添加孩子；默认落到健康档案。
- [x] 当前孩子被删除：清空本地选择；仍有其他孩子则打开选择器；没有孩子则育儿页空态；首次启动 / 无本地偏好时默认入口落到健康档案。
- [x] 两台设备独立：用两个 context 实例模拟，设备 A 选豆豆、设备 B 选老二，互不覆盖；事件仍以 `member_id` 归属。
- [x] 育儿页左上角 `豆豆 ▾` 可打开选择器；多孩子只列孩子，单孩子锁定显示名字；选择器含「管理成员」入口；健康档案显示当前成员并可列全部成员。
- [x] 不新增账号 / 邀请 / 云同步；不写全局 active child。
- [x] RNTL：单孩子锁定、多孩子选择持久化、成人当前成员不影响育儿、无孩子回落、删除孩子回落、选择器管理成员、双设备独立。

## 实现提示

- 现有 `CurrentMemberContext` 已管理成员选择；本票只补「当前孩子」派生与持久化，不重写成员加载。
- 单孩子判定用 `is_child`（由出生日期实时计算），不新增字段。
- 选择器可复用现有成员 chips 的样式；育儿场景过滤 `is_child`。
- 测试用 mock 成员列表覆盖 0 / 1 / 多孩子、成人、删除；不要依赖真实后端。
