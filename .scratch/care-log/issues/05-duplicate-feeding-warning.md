# 05: 重复喂养提示（5 分钟窗口）

**What to build:** 保存喂养事件前，检查同一孩子最近一条喂养；若距当前时间 ≤ 5 分钟且不是正在修改的同一条，弹确认「刚刚已有一条喂养记录（14:05 · 奶粉 120 ml），仍然添加？」。不自动合并、不服务端去重、不阻塞。

**Blocked by:** 04（记录弹层与目标孩子）。

**Status:** resolved

## 验收清单

- [x] 常量 `DUPLICATE_FEED_WINDOW_MINUTES = 5` 集中定义；窗口内判定使用同一 `member_id` + `type=feed`。
- [x] 触发时显示确认弹层，包含上一条的时间与摘要；按钮「仍然添加」/「返回修改」。
- [x] 「仍然添加」保存第二条；「返回修改」不落库、保留表单内容。
- [x] 修改同一条喂养事件不触发；不同孩子、不同事件类型不触发。
- [x] 跨设备并发是 best-effort：不做服务端去重、不做全局锁；必要时在文案或注释中说明。
- [x] 不新增服务端接口；读取最近喂养复用 01 的读模型 / 今天数据。
- [x] RNTL：窗口内触发、窗口外不触发、不同孩子不触发、修改不触发、仍然添加 / 返回修改两条路径。

## 实现提示

- 在保存按钮的提交前做检查，而不是在输入时；避免每次输入都查询。
- 最近喂养可以从今天页已加载事件取；若跨午夜 / 跨天，读取当天最早需要的一条，保证窗口判断正确。
- 确认弹层复用现有确认对话框样式；不要把「仍然添加」做成危险红色，它不是删除。
- 5 分钟是建议值，真实使用后再调；不要把它写成医学建议或喂养间隔。
