# 04: 分析事实层与结果页

**What to build:** 家长从项目详情页点「分析这个项目」，看到本次纳入的报告与病历范围、偏离参考范围的指标、与本人历史比较、相关病历诊断原文、未纳入项及原因。首次点击时展示数据去向确认；结果页底部固定展示来源声明。

**Blocked by:** 01 成员模型扩展, 03 病历作为叙述型报告

**Status:** ready-for-agent

- [ ] `POST /analyses` 接受 `member_id`、`panel`、`entry`、`indicator_name?`、`report_sha?`、`window_months`
- [ ] 窗口默认最近 12 个月、每趋势键最多 6 个有效点，两个边界同时生效
- [ ] 有效点判定五项条件全覆盖：同成员、同趋势键 + 同 canonical unit、`unit_status = verified`、`flag ≠ not_tested` 且有日期、通过信任门控
- [ ] 默认排除项不被引用为结论依据
- [ ] 稀疏时扩展至 24 个月或最多 4 个点并标注「历史数据较少」
- [ ] 项目详情页与单指标入口都能进入；单指标自动扩展至所属 Panel 并提示范围
- [ ] 事实层输出纳入范围、偏离项、历史比较、病历诊断与处理原文、未纳入原因
- [ ] 首次点击展示数据去向确认，之后不再展示
- [ ] 结果页底部展示来源声明
- [ ] 快照记录成员、Panel、窗口、有效点集合、病历引用与规则版本
- [ ] App 结果页只渲染事实层时不报错
- [ ] HTTP 测试覆盖窗口、门控、排除、稀疏扩展；RNTL 覆盖结果页与首次确认
