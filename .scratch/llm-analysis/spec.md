# Spec：医学领域 LLM 分析（llm-analysis）

Status: ready-for-agent

**范围：** 成员信息扩展（性别 / 出生日期）、生长记录、病历（作为叙述型报告）、LLM 分析的三层输出、知识条目库、框架层计算规则、分析入口、回溯窗口、云端调用与脱敏、配额。

**不含：** 诊断与治疗建议、运行时抓取指南全文、病历页面的视觉细节、全量异常分析（二期）、`visit` / `diagnosis` 规范化表。

**替代：** 吸收 `draft.md`、`docs/2026-11-02-panel-sources.md`、`referrence.md` 的全部有效内容；这三份文件已删除。

## 1. Problem Statement

家长把检查单拍照归档后，能看到数值、单位、参考范围和 flag，但不知道「这对我意味着什么」。现有产品只陈述事实，不做解读，这是有意的边界；但直接让 LLM 自由解释会立刻越界——成员没有年龄和性别，档案里没有病历，模型只能凭几个异常 flag 猜病因。

同时，产品只有检查报告，没有病历。医生的诊断、医嘱和随访计划留在纸上，没有进入档案。结果是每次分析都从零推断，连「医生上次说是什么问题」都不知道。

## 2. Solution

把 LLM 的输出拆成三层，有哪层出哪层：

- **事实层**：纳入范围、偏离参考范围的指标项、与本人历史的比较、相关病历原文、未纳入项及原因。只依赖数据，永远可用。
- **框架层**：代码算得出的判读标签——肝功 R 值分型、转氨酶分级、AST/ALT 比、贫血形态学分类、按年龄性别的切点偏离、BMI 百分位。只有实现了规则的 Panel 才有。
- **解释层**：四段式（可能原因 → 进一步检查 → 生活建议 → 长期跟踪），医学原文逐字取自审核过的知识条目，模型只负责跨条目组织与病历对齐。

病历复用叙述型报告链路，作为 `report_type = clinical_note` 的报告，不建 `visit` / `diagnosis` 表。LLM 主要工作从「推断病因」变成「把医生写下的诊断与本次检验数据对齐」。

云端 API 只接收脱敏后的证据包；配额只锁解释层，前两层不耗 token，额度用完产品仍可用。

## 3. User Stories

### 成员与生长记录

1. 作为家长，我想在建成员时填写性别和出生日期，以便系统能选对年龄段参考区间与切点。
2. 作为家长，我想只填出生日期而不填年龄，以便明年不用改设置。
3. 作为家长，我想在性别不确定时选择「不确定」，以便不被强迫二选一。
4. 作为家长，我想给成员补录身高体重和测量日期，以便系统能算 BMI。
5. 作为家长，我想记录身高体重来自实测、体检单还是手输，以便知道这个数有多可信。
6. 作为家长，我想在成员列表看到最近一次身高体重与测量日期，以便判断数据新旧。
7. 作为家长，我想修改成员性别和出生日期，以便填错后可以纠正。

### 病历

8. 作为家长，我想上传病历照片并被识别为一份病历报告，以便不用逐字手输。
9. 作为家长，我想看到病历的段落原文（主诉 / 现病史 / 诊断 / 处理），以便核对系统没有改写医生的措辞。
10. 作为家长，我想在切不出段落时看到整页原文，以便信息不丢。
11. 作为家长，我想通过日期把病历和检验报告并排查看，以便还原一次就医。
12. 作为家长，我想知道病历内容来自 OCR 还是手输，以便判断是否需要核对。

### 分析入口

13. 作为家长，我想在项目详情页点击「分析这个项目」，以便看到该项目全部指标的趋势和相关病历。
14. 作为家长，我想从单个异常指标进入分析，以便系统自动扩展到所属项目组并提示范围。
15. 作为家长，我想从趋势页进入分析，以便从正在看的曲线继续。
16. 作为家长，我想在分析前调整时间范围（6 / 12 / 24 个月），以便查看更长或更短的历史。
17. 作为家长，我想在分析前看到本次使用的数据范围，以便知道结论基于哪些报告和病历。

### 三层输出

18. 作为家长，我想看到本次纳入了哪些报告和哪些病历，以便确认范围。
19. 作为家长，我想看到每个偏离参考范围的指标值、单位、参考范围和日期，以便自己核对。
20. 作为家长，我想看到这个值在本人历史上是升高还是下降、是否为最近一段时间的最高或最低，以便判断变化。
21. 作为家长，我想看到相关病历里的诊断原文，以便知道医生当时的判断。
22. 作为家长，我想看到肝功的 R 值分型和转氨酶升高分级，以便理解是哪种类型的异常。
23. 作为家长，我想看到「肝细胞型（转氨酶升高为主，碱性磷酸酶不明显升高）」这样的固定解释，以便读懂术语。
24. 作为家长，我想看到血常规的形态学分类，以便理解贫血的方向。
25. 作为家长，我想看到 BMI 和年龄性别百分位，以便知道体格发育位置。
26. 作为家长，我想在数据不足以支持判断时看到明确说明，而不是一段含糊的话。
27. 作为家长，我想在某个 Panel 没有审核条目时仍然看到事实层和框架层，以便功能不整体失效。
28. 作为家长，我想看到四段式解释时知道每条结论的依据来源，以便判断可信度。
29. 作为家长，我想点开「查看依据」看到标准或指南名称，以便自己查证。
30. 作为家长，我想知道哪些数据因为未核对低置信被排除，以便理解结论的局限。

### 安全与边界

31. 作为家长，我想系统绝不输出诊断结论，以便不会把工具当成医生。
32. 作为家长，我想系统不改写医生写下的诊断，以便原文可追溯。
33. 作为家长，我想病历和检验数据冲突时看到并列陈述，而不是系统替我判断谁对。
34. 作为家长，我想系统不根据病历诊断反推本次结果的原因，以便避免虚假因果。
35. 作为家长，我想系统不推荐药物、剂量或治疗方案，以便不越过医疗建议边界。
36. 作为家长，我想手输的身高体重只显示 BMI 数值而不给超重判定，以便不把非实测数据当筛查依据。
37. 作为家长，我想系统明确标出「早于分析窗口」的病历，以便知道那是背景而非本次依据。
38. 作为家长，我想系统在发送云端前去掉姓名、生日、机构和原图，以便健康数据不超出必要范围。
39. 作为家长，我想知道分析有每日次数上限，以便理解什么时候解释层不可用。

### 复盘与配额

40. 作为家长，我想每次分析保存一份数据快照，以便之后能复现当时的结论。
41. 作为家长，我想快照包含使用的报告、指标点、病历引用、规则版本与条目版本，以便区分「数据变了」和「规则变了」。
42. 作为家长，我想在新报告或诊断修改后看到旧分析被标记「数据已更新」，以便知道结论可能过时。
43. 作为家长，我想在配额用完时仍能看事实层和框架层，以便功能不整体停摆。
44. 作为家长，我想对明显不合理的解释点「这不对」，以便反馈问题。
45. 作为家长，我想第一次使用分析时知道数据会发送到云端的哪些内容，以便决定是否使用。
46. 作为家长，我想在结果页看到内容来源说明，以便知道这不是诊断。
47. 作为家长，我想在条目更新后看到「依据已更新」，以便知道旧结论可能过时。

## 4. Implementation Decisions

### 4.1 成员模型扩展

成员新增 `sex`（`male` / `female` / `unspecified`）与 `birth_date`，两者 **`NOT NULL`**。**不存静态年龄**：年龄每年变化，必须由 `birth_date` 实时计算。

`birth_date` 允许 `birth_date_precision`（`day` / `year`）；只知道年份时填当年 1 月 1 日并标 `year`，避免 0–1 岁段算错。

`is_child` 保留，可由 `birth_date` 派生，但为兼容既有 UI 不删除、不自动改写。

**迁移是破坏性的**：产品未上线，迁移脚本先把 `reports.member_id` 置空，再清空 `members`（不用 `TRUNCATE members CASCADE`，避免连带清空 `reports`）。迁移说明必须标注这是仅限未上线阶段的操作。

这与 `CONTEXT.md` 当前定义（「成员只有显示名与是否孩子两档信息」）和 `viz-and-client` spec 冲突。实施时必须同步更新 `CONTEXT.md` 并新增 ADR，记录成员模型扩展。

### 4.2 生长记录

身高体重是会变的测量值，不放成员表，存为 `growth_record`：

- `member_id`
- `measured_on`
- `height_cm`、`weight_kg`（可单填）
- `source`：`measured` / `report` / `manual`

`BMI = 体重(kg) / 身高(m)²`，用测量时点的值实时计算，不缓存。分析取最近一次测量并标注日期；报告日期与测量日期不同时，以测量日期为准。

WS/T 586—2018 要求身高体重为实测值，不得用问卷或自报。`source = manual` 时只输出 BMI 数值，不输出超重 / 肥胖判定标签。

### 4.3 病历

病历复用叙述型报告链路（ADR-0009），作为 `report_type = clinical_note` 的报告，不是独立实体。

`sections` 的 `kind` 扩展（现有 schema 的 `kind` 是开放字符串，不新增枚举约束）：

| `kind` | 内容 |
| --- | --- |
| `chief_complaint` | 主诉 |
| `present_illness` | 现病史 |
| `diagnosis` | 诊断 |
| `treatment` | 处理 / 医嘱 |
| `note` | 兜底：切不出段落时整页原文 |

段落切分按标题词全自动；切不出来就把整页 OCR 作为单个 `note` section。**不建 `visit` / `diagnosis` 表**，不做诊断结构化。

规则：

1. 病历只作引用来源，不作推理前提。可以引用「2026-05 · 缺铁性贫血」，不能据此推断「这次贫血是因为缺铁」。
2. 诊断与处理逐字引用，不翻译、不概括、不补全缩写。
3. 病历与检验数据不一致时并列陈述，不判断哪一方正确，也不解释差异原因。
4. 未核对的 OCR 病历内容按低置信处理，不进入结论依据。
5. LLM 只引用 `diagnosis` 与 `treatment` 段落；`chief_complaint` 与 `present_illness` 不发送云端（见 §4.11）。
6. 一次就诊关联多份报告 v1 不支持，用日期邻近匹配；需要时另加工单，只加分组，不动诊断。
7. 不做病历与条目解释的自动冲突检测。两者并列呈现；关键词规则会误报（「排除其他原因后诊断为 X」里也有「排除」），误报比不报更伤信任。

### 4.4 输出三层

| 层 | 内容 | 触发条件 | 知识来源 |
| --- | --- | --- | --- |
| 事实层 | 纳入范围；偏离参考范围的指标项；与本人历史比较；相关病历诊断与处理；未纳入项及原因 | 永远输出 | 数据 + 病历 |
| 框架层 | 肝功 R 值分型与转氨酶分级、AST/ALT 比；贫血形态学分类；年龄段切点偏离；BMI 与年龄性别百分位 | 该 Panel 有已实现规则，且字段与成员信息齐全 | 代码计算 + 固定文案 |
| 解释层 | 四段式：可能原因 → 进一步检查 → 生活建议 → 长期跟踪 | 命中 `approved` 知识条目 | 知识条目库 |

分层规则：

1. 事实层不生成医学判断，任何 Panel 都能输出。
2. 框架层只输出规则算得出的标签，并附固定文案解释（见 §4.5），不解释病因。
3. 解释层缺条目时整层省略，不显示空状态；前两层照常输出，必要时附固定引导「本次没有可引用的解读条目，可以带着上面的数值问医生」。不得用「证据不足」替代前两层。
4. 事实层每个数值绑定证据点；解释层每条结论额外绑定条目 ID。
5. 参考区间与人群切点是两个口径：`flag` 一律按单据范围判定；切点标签只在数值越过切点时输出，并同时注明单据范围，避免「正常」与「低于切点」并列却没有解释。

### 4.5 框架层规则

首期只实现 `liver` 与 `cbc`，加体格：

| 规则 | 公式 / 判定 | 来源 |
| --- | --- | --- |
| 肝功 R 值 | `R = (ALT / ULN_ALT) ÷ (ALP / ULN_ALP)`；R ≥ 5 肝细胞型，R ≤ 2 胆汁淤积型，2 < R < 5 混合型 | AASLD / ACG |
| 转氨酶分级 | < 2×ULN 临界；2–5× 轻度；5–15× 中度；> 15× 重度 | ACG 2016 |
| AST/ALT 比 | 直接相除 | AASLD |
| 贫血形态学 | MCV / MCH / MCHC + RDW 组合 | 见 §7.1 |
| 贫血切点偏离 | WHO 2024 Hb 切点，按年龄段分档 | WHO 2024 |
| BMI | `体重(kg) / 身高(m)²`；6–18 岁按 WS/T 586 性别年龄别界值；5–19 岁可用 WHO 2007 z-score | WS/T 586—2018 / WHO 2007 |

**标签固定解释**（代码渲染，不走模型）：

| 标签 | 家长文案 |
| --- | --- |
| 肝细胞型 | 转氨酶升高为主，碱性磷酸酶不明显升高 |
| 胆汁淤积型 | 碱性磷酸酶升高为主，转氨酶不明显升高 |
| 混合型 | 转氨酶和碱性磷酸酶都升高 |

R 值边界在 AASLD 与 ACG 之间有 `≥5` / `>5`、`≤2` / `<2` 的差异。实现时固定一种口径并注明来源，不混用。

### 4.6 知识条目

条目存为 YAML，放在 `internal/analysis/knowledge/`，与 Go 分析代码一起评审；用 git diff 审核，不建管理界面。不放在 `recognizer/`，避免让人误以为识别端在消费它。

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定标识，输出必须引用 |
| `priority` | 多条目命中时的排序，数字小的优先 |
| `trigger` | Panel + 趋势键集合 + flag 组合，可选趋势条件 |
| `explanation` | 可能原因，面向家长的审核原文 |
| `check_directions` | 进一步检查，可为空，属方向说明 |
| `general_advice` | 生活建议，可为空，不得含药物、剂量、治疗方案 |
| `track_items` | 建议持续记录的趋势键 |
| `source_ids` | 标准号 / 指南名 + 条款或页码 + 链接，由代码渲染 |
| `required_context` | 判读时通常还需一起看的指标或信息 |
| `review` | `decision`（`accepted` / `rejected`）、`reviewed_at`、`note` |
| `version` | 条目版本，分析快照记录 |

**审核**：审核人是产品维护者本人，单人审核，无第二人复核。只记录 `decision` 与 `reviewed_at`，不记录 `reviewed_by`；否决时写一句 `note`。医学准确性依赖单人判断，这一风险记入 §7.4。

**匹配**：精确匹配优先；多命中按 `priority` 排序取前 2 条；部分匹配一律不输出；无命中省略解释层。

知识条目只服务解释层。条目库与规则一起版本管理，保留变更记录。

### 4.7 内置依据的边界

**可以内置：** 标准名 / 代码 / 单位 / 项目组归属（复用既有词典）；`required_context`；判读必需但检查单未覆盖的信息（缺症状、缺病程时明确列出）；可计算规则与年龄性别切点；每个 Panel 的来源链接。

**不内置：**

- **参考区间覆盖规则**：单据有范围时以单据为准，不叠加国标。单据无范围时，若该指标有国标且成员信息可映射年龄段，用国标补，标注「国标参考区间，非本实验室范围」。两者都无时标「无法比较」。
- **诊断标准**：WHO 2024 等切点只作框架层标签（「低于该年龄段切点」），不输出「贫血」诊断结论。诊断由病历里的医生给出。依赖症状、重复测量或 BMI 的规则（糖尿病、高血压、代谢综合征）不内置。
- **指南级筛查与随访建议**：适用条件（BMI、家族史、症状）无法匹配，不写成条目。
- **运行时抓取指南全文**：模型不访问网络。理由：模型自行解释原文会绕过审核门；网页版本漂移导致同一问题不同时间答案不同、不可复现；实测卫健委 HTML 页对脚本请求返回 412。需要指南内容时走离线批处理生成条目草案，再人工审核。

### 4.8 分析入口

| 入口 | 定位 | 位置 |
| --- | --- | --- |
| Panel | 主入口 | 项目详情页顶部 |
| 单指标 | 辅助 | 趋势页 |
| 病历 | 辅助 | 病历详情页 |
| 全量异常 | 二期 | — |
| `report_type` | 不作默认入口 | — |

规则：默认输入只含该 Panel 的指标；`panel = other` 只输出事实层；家长修正过指标名但 Panel 未按 ADR-0012 重算的，标「项目归属未重算」，不参与框架层与解释层。

### 4.9 回溯窗口与快照

| 数据类型 | 默认 | 说明 |
| --- | --- | --- |
| 同一趋势键 | 最近 12 个月内、每趋势键最多 6 个有效点 | 两个边界同时生效 |
| 同 Panel 关联指标 | 与主窗口对齐 | 横向时间一致 |
| 病历 | 窗口内全部 + 最近一次相关 | 窗口外那次标「早于分析窗口」 |
| 更早历史 | 默认不进入 | 仅稀疏扩展或用户手动加长 |

窗口锚点是分析时刻当日，不是最近一份报告的日期。

**有效点判定**（全部满足）：同一成员；同一趋势键（`code` > `loinc` > 规范名）+ 同一 canonical unit；`unit_status = verified`；`flag ≠ not_tested` 且有 `report_date`；通过信任门控（`review_status ∈ {confirmed, corrected}` 或 `low_confidence = false`），取修正后的最终值。

**默认排除：** 未核对低置信点（展示保留，不作依据）、超窗口、跨成员、`not_tested`、`unit_status = unverified`、跨单位、无日期、`failed` 与叙述型报告（`clinical_note` 除外）、与当前 Panel 无关的指标。

`unknown` 不构成偏离证据，单独列为「无法与参考范围比较」。

**稀疏扩展：** 某趋势键 12 个月内有效点 < 2 时，向前扩展至 24 个月或最多 4 个点，标注「历史数据较少」，禁止无限回溯。

**密集时：** 不按「有变化或持续异常」优先保留，那会制造选择偏差。

**用户调整：** 只改时间边界（6 / 12 / 24 个月），不改变信任门控、Panel 边界、单位门控与有效点判定。

**快照：** 永久保留。新报告、病历新增或修改、核对状态变化后，旧分析标 `stale=true`，仍可查看，展示时标注「数据已更新」。条目版本变化时标 `entry_updated=true`，展示「依据已更新」，不自动重跑、不修改历史内容。

### 4.10 API 契约

| 方法与路径 | 用途 | 关键约定 |
| --- | --- | --- |

### 4.11 云端调用、脱敏与配额

**部署：** 云端 API（DeepSeek）。服务仍在内网，只允许出站 HTTPS，不暴露公网；`ADR-0006` 的局域网前提保留，只新增出站例外。无本地 GPU。

**脱敏**（发送给模型的字段）：

| 发 | 不发 |
| --- | --- |
| 指标规范名、数值、单位、参考范围、flag | 成员姓名 |
| 相对时间（`T-0` / `T-3m`） | 出生日期、精确报告日期 |
| 年龄段（如 `5–6 岁`） | 机构名、科室名、医生名 |
| `diagnosis` 与 `treatment` 段落原文 | 原图、OCR 原文（除上述两段） |
| 条目原文与 `source_ids` | 报告编号、图像哈希 |
| 未纳入原因码 | `chief_complaint`、`present_illness` |

主诉与现病史常含「最近不爱吃饭」这类可识别的生活细节，是脱敏的主要泄漏点，一律不发送。

**配额**（配置项，不写死）：

| 限制 | 默认值 | 超限行为 |
| --- | --- | --- |
| 单次 input | 8k tokens | 裁最旧证据点，不裁条目原文 |
| 单次 output | 1.5k tokens | 截断并标注 |
| 每天每家庭 | 20 次 | 解释层不可用，事实层 + 框架层照常 |
| 单次超时 | 30 秒 | 同配额用完 |

**失败处理：** JSON 不合法、校验失败、超时、配额用尽 → 重试 1 次 → 仍失败则省略解释层并标注原因。前两层不受影响。

**配额用尽 UX：** 按钮仍可点击；解释层位置显示「今日额度已用完，事实与判读仍可用」，不静默降级、不禁用按钮。禁用会让家长以为整个功能坏了。

### 4.12 模型职责与输出校验

模型不写医学断言，只做跨条目组织。

| 任务 | 谁做 | 可验证性 |
| --- | --- | --- |
| 条目匹配 | 规则（精确匹配 + `priority`） | 完全可验证 |
| 证据选择 | 规则（窗口 + 门控） | 完全可验证 |
| 单条目医学原文 | 代码从条目拼接 | 逐字可验证 |
| 跨条目的顺序与过渡 | 模型 | 结构可验证 |
| 病历与数据的对齐 | 模型 | 引用可验证 |
| 未纳入项的解释 | 模型 | 原因码可验证 |

模型输出：

```json
{
  "sections": [
    {
      "kind": "fact | framework | explanation",
      "entry_id": "liver-hepatocellular-mild",
      "evidence_ids": ["ev-1", "ev-2"],
      "bridge_text": "……"
    }
  ]
}
```

服务端校验 `bridge_text`：

1. 出现的数字必须能在 `evidence_ids` 中找到；
2. 不得含禁用推断词（`可能` `提示` `考虑` `建议` `应该`）；
3. 长度 ≤ 200 字；
4. `entry_id` 必须存在且 `review.decision = accepted`。

任一不通过，拒绝该 section；全部不通过则省略解释层。

医学原文（`explanation` / `check_directions` / `general_advice`）由服务端从条目直接拼接，模型无法修改。

### 4.13 反馈与观测

**用户反馈**：每个分析结果提供「这不对」按钮，记录 `analysis_id`、`entry_id`（可选）、用户填写的理由、时间。只记录，不自动降级条目——误点会误伤，且家庭规模下累计阈值永远达不到。

**服务端日志**：记录所有降级事件——LLM 超时、JSON 不合法、`bridge_text` 校验失败、配额用尽、信任门控全未通过、条目未命中。

**周检**：每周看两个比率——用户反馈率（反馈数 / 分析数）与降级率（降级次数 / 分析数）。前者发现内容错，后者发现链路坏。

### 4.14 合规与告知

**首次使用确认**（只弹一次，之后记住）：

> 分析会把本次涉及的检验数值、年龄段和病历诊断发送到云端服务处理，不包含姓名、生日、机构名和原图。结果不是诊断，不能代替医生。

**结果页固定声明**：

> 内容来自你上传的检查报告、病历和公开检验标准，不是诊断。

两句都不使用「免责」措辞；它们说明的是数据去了哪、内容是谁说的，而不是法律话术。

本 spec 不承诺合规。服务商条款、儿童数据要求由法务判断；技术侧只保证 §4.11 的脱敏清单被执行。

### 4.15 规则汇总

1. 解释层医学原文只能逐字取自 `accepted` 条目；模型只写 `bridge_text`，不得改写医学含义。
2. 事实层只陈述数据与病历原文；引用病历中的「考虑」「可能」时必须加引号。
3. 指标项进入事实层必须通过信任门控；全未通过时事实层降级为「证据不足，请先核对」，框架层与解释层不输出。
4. 事实层每个数值绑定报告日期、趋势键、数值、单位、flag；解释层每条结论还必须绑定条目 ID。
5. 无命中条目时省略解释层，不显示空状态；必要时附固定引导「本次没有可引用的解读条目，可以带着上面的数值问医生」。
6. 生活建议不得含药物、剂量、治疗方案；儿童成员只能使用明确标注适用于儿童的原文。
7. 参考区间遵守 §4.7 覆盖规则；年龄由 `birth_date` 实时计算。
8. 身高体重只读带日期的 `growth_record`；BMI 实时计算；手输数据不输出超重 / 肥胖标签。
9. 标准名、标准号与条款只能由代码从 `source_ids` 渲染，模型不得自行书写依据。
10. 发送云端前必须执行 §4.11 脱敏；`chief_complaint` 与 `present_illness` 永不发送。
11. 配额只限制解释层；前两层不调 LLM，不消耗配额。
12. 首次使用必须展示数据去向确认；结果页固定展示来源声明。
13. 不做病历与条目解释的自动冲突检测，两者并列呈现。

## 5. Testing Decisions

**好测试只测外部行为**：不测内部实现细节；契约形状由 fixtures 锚定，行为由集成测试锚定。

**Seam（三层）：**

1. **HTTP `/api/v1`（主 seam）**：httptest 起 handler 栈，以既有编排层 fakes 打底。覆盖成员 CRUD、生长记录、病历上传、`POST /analyses` 全链路。
2. **`internal/analysis` 纯函数包（唯一新增内部 seam）**：有效点筛选、窗口取交集、R 值、转氨酶分级、AST/ALT、BMI、年龄段映射、条目匹配、脱敏、分层组装、`bridge_text` 校验。
3. **LLM 客户端接口（注入 fake）**：协议、重试、配额、降级。不打真实模型。

**App**：RNTL 测成员表单（必填校验、`unspecified`）、生长记录（来源选择）、病历段落展示、分析结果三层渲染、「查看依据」、`stale` 标记、配额提示。

**测试矩阵：**

- 正常：Panel 内多个异常指标 + 窗口内病历 → 三层完整输出。
- 边界：无病历；病历早于窗口；单据无参考范围但有国标；手输身高体重；`panel = other`；`birth_date_precision = year`。
- 错误：信任门控全未通过；条目缺失；`bridge_text` 含数字但不在证据里；`bridge_text` 含禁用词；JSON 不合法；超时。
- 脱敏：发送的 payload 不含姓名、生日、机构、医生、主诉、现病史、原图、报告编号。
- 配额：第 21 次请求返回前两层 + `explanation_available=false`。
- 冲突：病历诊断与本次数据不一致，输出并列陈述且无因果判断。
- 排除：跨单位、`not_tested`、`unverified`、无日期、跨成员均不进入事实层。
- 失效：新增报告后旧分析 `stale=true`。

**Prior art：** `.scratch/viz-and-client/spec.md` 的 HTTP fixtures + 编排层 fakes；`.scratch/abnormal-trends/spec.md` 的序列选择单测；`apps/mobile/src/test/` 的 RNTL 结构。

### 5.1 评估集（区别于工程测试）

| 层 | 来源 | 规模 | 执行 |
| --- | --- | --- | --- |
| 事实层 | 复用现有 golden 报告，手工补成员年龄性别，脚本生成期望输出并快照 | 约 100 case | CI |
| 框架层 | 构造边界用例：R 值 1.9 / 2.0 / 4.9 / 5.0，BMI 百分位在界值上下，切点跨年龄段 | 约 20 | CI |
| 解释层 | 真实数据输出 + 人工盲评 | 每季度 20 条 | 人工 |

**期望值冻结**：事实层与框架层的期望输出由代码生成一次、人工确认一次、然后冻结为 fixture。不能每次运行重新生成，否则测试永远通过。

**盲评**：隔一个月再看自己写的条目在真实数据上的输出。「当时觉得对」是单人审核最大的风险，隔一段时间才看得出来。

## 6. Out of Scope

- 诊断结论、治疗建议、药物与剂量。
- 分级分诊（观察 / 复查 / 就医）。
- WHO / ADA / KDIGO 的完整诊断规则套用（缺症状、空腹状态、重复测量）。
- 运行时抓取指南全文。
- 全量异常分析入口。
- `visit` / `diagnosis` 规范化表与「一次就诊关联多份报告」。
- 病历页面的视觉设计与信息架构细节。
- 成员扩展字段：过敏史、长期用药、家族史、孕产状态。
- 影像 / 叙述型报告的 LLM 分析（`clinical_note` 除外，ADR-0009）。
- 本地模型部署。
- 增强路线（允许模型推理，由验证器兜底）。
- 病历与条目解释的自动冲突检测。
- 「可问医生的问题」生成。

| 凝血 | PT / APTT / INR、纤维蛋白原、D-二聚体解读；DIC 评分思路 |

具体切点数值以实现时引用的原始标准为准，不在本 spec 固化。

### 7.3 与既有文档的冲突

- `CONTEXT.md` 成员定义需从「显示名 + 是否孩子」扩展为「显示名 + 是否孩子 + 性别 + 出生日期 + 出生日期精度」。
- `viz-and-client` spec 的「成员最小模型」与离线队列假设需重新评估；服务仍在内网，但允许出站。
- `panel-browse` §3「文案中性」与 `viz-and-client` 故事 35「绝不出现诊断 / 处方 / 解读」按 §7.4 的范围放宽。
- `medical-standardization` 决策 #1「参考范围只从单据抽取」调整为「单据优先、国标补缺」。

### 7.5 关键假设与风险

- 家长能理解框架层标签；靠固定文案缓解，未验证。
- 与本人历史比较比与人群比较更有用；未验证。
- **单人审核**：解释层的医学准确性依赖产品维护者本人的判断，没有第二人复核。这是已知风险，不是待办。
- **解释层覆盖率可能长期低于 30%**：约束路线下，条目没写的组合就没有解释。产品必须接受大多数分析只有前两层；如果这个结果不可接受，应换增强路线，而不是继续加条目。
- 云端 API 依赖外部服务；失败时降级到前两层，不影响事实层。
- 脱敏后仍存在重识别风险：年龄段 + 稀有指标组合在小范围内可能指向个体；已去掉姓名、精确日期、机构，但不承诺匿名化。
- 体检单或实测数据能覆盖足够多的身高体重；否则肥胖判定不可用。
- **不做自动冲突检测**：家长可能同时看到病历原文和条目解释中的相反表述，系统不提示矛盾。
- **不预留增强路线接口**：未来若要允许模型推理，需要重构分析层与验证器，不是加配置开关。

### 7.6 第一批知识条目

首期只做一条，用于打通解释层链路：

```yaml
id: liver-hepatocellular-mild
priority: 10
trigger:
  panel: liver
  any_flag_high: [ALT, AST]
  all_normal: [ALP, 总胆红素]
explanation: >
  转氨酶升高而碱性磷酸酶和胆红素正常，通常提示肝细胞受累，
  而不是胆道淤积。
check_directions:
  - 复查肝功能，观察是否持续升高
general_advice: []
track_items: [ALT, AST]
source_ids:
  - standard: AASLD
    note: R 值分型与肝细胞型定义
review:
  decision: accepted
  reviewed_at: 2026-11-02
  note: 单人审核
version: 1
```

`explanation` 中的「通常提示」经确认不算越界；`check_directions` 中的「复查」经确认不算被禁的复查提醒。
