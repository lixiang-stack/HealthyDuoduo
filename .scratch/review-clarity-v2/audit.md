## 2. 口径与首匹配规则

### 2.1 `ComputeFlag` 同口径

`audit.py` 的 `compute_flag()` 与 `internal/pipeline/flag.go` 同语义：

- `value` 必须是纯数值字符串（`float` 可解析）；`<2.00`、`70-80`、`阴性`、`1-2` → `unknown`。
- 参考范围只接受 `a-b` / `a--b` / `a~b`（含 `–`/`—`）与 `<v` / `≤v` / `>v` / `≥v`；**标量 `0` / `0.0` 不接受**。
- 区间上下界写反（`lo > hi`）→ `unknown`；单侧比较仍按现有语义比较。
- `value=null` 或 `ref=null` → `unknown`。

自测向量见 `audit.py --self-test`；`schemas/testdata/flag.vectors.json` 是 Go/Python 双侧共享语义源。

### 2.2 根因定义

| 根因 | 判定 | 不是 |
| --- | --- | --- |
| `OCR 漏识别` | 值/范围不在 OCR 期望输出中，或只输出无法解析的残片（如 `0.00-.'0`、`410`、`82-8`）；原图/OCR 行文本可证明“没有可配对的输入” | 不是“纸面没有”；也不是“值在 OCR 里但没配对” |
| `OCR 行合并` | 反向/粘连串已出现在 OCR 行文本中，且是相邻格/手写批注的拼接；正确值/范围可从原图或相邻 OCR 列恢复 | 不是 `_decompose` 跨格合并；它只拆单格 |
| `提取器配对` | 值/范围已在 OCR 输出中（同一行、另一行或另一个字段），但未归到该指标项，或归到了相邻项/`unit` | 不是 OCR 漏识别 |
| `纸面无参考范围` | 有数值；原图该行没有参考范围，OCR 也没有 | 不是“raw_text 没有范围 token” |
| `不可比较` | 定性文本 / 单侧比较式值 / 区间型值；即使补全字段，`ComputeFlag` 仍为 unknown | 不是缺值 |
| `参考范围不可解析` | ref 是标量或其它非区间/非单侧比较；即使抽取正确，`ComputeFlag` 仍为 unknown | 不是区间写反（写反归 OCR 行合并/漏识别） |
| `其他` | 无原图、OCR 只有名称、叙述体报告、证据不足 | — |

### 2.3 首匹配顺序（避免一项进两类）

按以下顺序命中即停：

1. `value` 存在且不可数值化 → `不可比较`（定性/单侧/区间）。
2. `ref` 存在但不是区间/单侧比较（含标量） → `参考范围不可解析`。
3. `ref` 是反向区间或包含多个范围 token，且原串出现在 OCR 行文本 → 默认 `OCR 行合并`（跨格粘连）；若原图证明是单格误读（如 `80~5.10` 对应 `3.50~5.10`），证据表改判 `OCR 漏识别/范围误读`。
4. `value=null` 且 `ref` 存在：OCR 行文本有值候选 → `提取器配对`；否则 → `OCR 漏识别/值缺失`。
5. `value` 数值且 `ref=null`：OCR 行文本有范围候选 → `提取器配对`；否则按原图证据分 `纸面无参考范围` / `参考范围不可解析` / `OCR 漏识别` / `其他`。
6. `value=null` 且 `ref=null`：OCR 行文本有候选 → `提取器配对`；只有名称 → `OCR 漏识别`；无原图/叙述体 → `其他`。

因此，`cbc_04` 的 `淋巴细胞数`（缺值 + 反向范围）只计 `OCR 行合并`，不会再被计一次“缺值”；`2b9319` 的 ANA（当前 `value=1`、纸面定性）只计 `不可比较`，不会被计成“有数值 + 缺范围”。

**缺值 + 纸面定性**（如 `9da58`/`ua_05` 的尿潜血、尿糖）：当前 `value=null`，根因是 OCR 没有输出该值 → 计 `OCR 漏识别`，但 `operable=false`（补录后仍是定性值，`ComputeFlag` 不会变成 normal/high/low）。不要因为纸面是定性就改判 `不可比较`，否则会把 OCR 数据缺口藏进语义类；也不要把它算进“可修正”。

首匹配是规则引擎；需要原图才能判的项（纸面无范围、单格范围误读等）由脚本里的 `EVIDENCE` 证据表覆盖。member-去重 96 个 unknown 中，**35 个由规则自动分类，61 个由 OCR/原图证据表覆盖**；完全去重 78 个中为 **25 / 53**。`--items` 的 `source` 列会标 `rule` / `evidence`，每个覆盖项的 `note` 都写了 OCR 行号或原图观察。
